# Сборка и публикация 0.45.1

Команды ниже выполняются в распакованных исходниках. [Проверки выпуска](qa/0.45.1/RELEASE-VERIFICATION.md).

## Проверка и архивы

Нужны Python с пакетами из `requirements-dev.txt`, Node.js, Windows PowerShell 5.1. Нативные x86-проверки используют существующие библиотеки MoonLoader только для чтения; GTA не запускается. В изолированных средах перед этими проверками задайте корректный `LOCALAPPDATA` для дочернего процесса и `PA_SOURCE_ROOT` на папку кандидата.

```powershell
python -m pip install -r requirements-dev.txt
python tools/verify-package.py
python tools/run-regression0451.py --jobs 3
node tests/test_cef_chat.js
node tests/test_cef_adaptive0450.js
node tests/test_cef_recovery0450.js
python tools/run-platform0451.py --skip-installer
python tools/run-installer-shards0451.py
python tools/run-extra0451.py
```

Две дополнительные проверки CEF используют файлы клиента, доступные на конкретном ПК. Для воспроизведения проверки сохранённого `d7526…` задайте `PA_QA_HUD_SOURCE` на папку с его `main.js` и `index.html`. Эти сторонние файлы не распространяются в исходном пакете PA. Без них проверяется текущий клиент: при изменённом контракте честно фиксируйте BLOCKED / несовместимость, не добавляйте его хеш в разрешённые ради зелёного теста. All-in-One требует предварительного `tools/build-update.ps1`.

`tools/build-author0451.py` воспроизводит только публичные эталонные файлы из утверждённого документа и приложенного исходного авторского набора 0.45.0. Он не читает и не меняет файлы игры. Запуск нужен при намеренном изменении эталона, не при обычной сборке. `tools/refresh-manifest.py` обновляет контрольные суммы после проверки исходников; не используйте его для маскировки незнакомого изменения.

```powershell
python tools/refresh-manifest.py
python tools/verify-package.py
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-update.ps1
python tools/build-distribution.py
python tools/build-source0451.py
python tools/verify-artifacts0451.py
```

Перед упаковкой итоговый `docs/qa/0.45.1/STATE.json` должен честно отражать законченные тесты. При изменении исходников после прогона результаты устаревают: повторите затронутые проверки, затем общую регрессию и упаковку. Все три ZIP, публичные JSON и `SHA256SUMS.txt` находятся в `dist`. Обновление программы не содержит личного config или авторских пресетов.

## Публикация — только после отдельного разрешения

1. Перенести проверенные исходники в чистую рабочую копию `VIBAG-bg/Police-Assistant`. Сверить свежий HEAD, просмотреть diff, подтвердить отсутствие личных файлов и изменений защищённых компонентов. Чужие новые коммиты не перезаписывать.
2. Запустить проверки в этой копии. Убедиться, что версия 0.45.1 и состав архивов совпадают с проверенным кандидатом. Коммитить только согласованные исходники; бинарные ZIP не добавлять в git.
3. После разрешения отправить коммит в `main`. Получить фактический 40-символьный SHA этого коммита.
4. Сначала запустить проверку комплекта без отправки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/publish-release.ps1 -Commit <SHA_коммита> -VerifyOnly
```

5. После разрешения на выпуск запустить ту же команду без `-VerifyOnly`. Скрипт сверяет remote HEAD, создаёт новый релиз и проверяет размеры/хеши загруженных файлов; существующий релиз не заменяет.
6. Проверить фактические файлы и ссылки GitHub, состояние релиза и работу получения версии. Не сообщать о публикации лишь по успешной локальной упаковке.

Архив должен содержать `Police-Assistant-v0.45.1.zip`, `pa26-update.zip`, `Police-Assistant-v0.45.1-source.zip`, `pa-binds.json`, `pa-settings.json`, `SHA256SUMS.txt`. Для пользователей с worker 0.44.0 сохранить примечание об однократной полной установке.
