# Исправление резервных копий в 0.41.0

## Если обновление 0.40.4 остановилось

1. Закрой GTA и дождись окончательного результата помощника обновления. Не запускай установщик параллельно с ещё работающим обновлением.
2. Скачай **`Police-Assistant-v0.41.0.zip`** из [Releases](https://github.com/VIBAG-bg/Police-Assistant/releases/latest), распакуй весь архив в отдельную папку с коротким путём, например `C:\PA`.
3. Запусти **«Установить PA.cmd»**, выбери свою папку игры и установи PA. Существующие бинды, заметки, профиль и настройки сохраняются; установщик создаёт резервную копию перед записью.
4. Дождись успешного завершения и запускай GTA. Следующие обновления будет выполнять исправленный помощник.

На компьютере без этого сбоя переход кнопкой обновления остаётся доступным. Если сбой уже повторяется, повторное скачивание тем же старым помощником его не устраняет: старый код работает до установки новых файлов. Права администратора не снимают ограничение длины пути.

Если помощник сообщает, что восстановление ещё требуется, дождись его завершения; не удаляй вручную `pa26-update.pending`, журналы или резервные копии. Сообщение о готовности разрешает запуск игры только после проверки согласованной версии.

## Что изменено

Прежний помощник сохранял полное дерево исходных путей внутри папки копии. Уже существующий каталог `police_assistant_2026_preset_backup_…` добавлял ещё один длинный участок. На старой политике путей .NET такой адрес выходил за пределы MAX_PATH. В предоставленном снимке видна ошибка создания файла копии; конец адреса обрезан, поэтому точный исходный файл по снимку установить нельзя.

Новые копии получают короткие последовательные имена. Таблица в `BACKUP.json` хранит исходный относительный путь, имя файла копии и SHA-256. Имена не строятся из исходного имени, поэтому одинаковые имена из разных старых копий не конфликтуют. Сами старые резервные копии также сохраняются, ничего из них не исключается.

Установщик использует такой же принцип: `PLAN.json` связывает копии программы с их назначениями, `PERSONAL.json` — копии личных файлов с исходными путями. Откат читает записанную таблицу. Существующие копии старого формата не преобразуются и не удаляются; новый помощник умеет восстанавливать прежние журналы.

Проверка хешей, запись журнала до замены файла, запрет смешанной загрузки и защита новых личных изменений сохранены. Замороженный `pa26_update_platform.lua` и адаптеры CEF не меняются.

## Как проверяется

`tests/test_update_legacy_paths.ps1` запускается Windows PowerShell 5.1 в отдельном процессе и включает старые ограничения путей .NET только внутри этого процесса. Реестр и системная настройка длинных путей не меняются. Тест воспроизводит отказ прежнего адреса, устанавливает новые файлы с вложенными копиями и кириллическими именами, проверяет совпадение байтов, откат на разных шагах и чтение старого журнала. Он добавлен в проверки GitHub.

Результаты объединённой сборки публикуются в [release-validation.json](release-validation.json). Проверки выполняются на макетах игры; запуск GTA/сервера и испытание на отдельной виртуальной Windows 7 не заявляются.
