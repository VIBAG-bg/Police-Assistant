# Переносимость проверки установщика

Первый [GitHub-прогон](https://github.com/VIBAG-bg/Police-Assistant/actions/runs/41859281367) прошёл Lua, CEF, worker и legacy-path проверки, затем остановился: общий тест установщика читал `main.js` по абсолютному пути рабочего ноутбука. На чистом Windows runner такого файла нет. Это ошибка самодостаточности теста; изменение CEF-контракта клиента причиной этого сбоя не является.

`tests/test_installer.ps1` теперь создаёт собственный тестовый пакет через `tests/support/installer-cef-fixture.ps1`. Копия размещается только внутри `tests/install-sandbox`. Синтетический JS объявлен известным **только в двух согласованных копиях реестра этого тестового пакета**; его SHA и изменённый модуль отражены в тестовом manifest. Байты самого установщика совпадают с production. Исходные manifest, реестры и runtime PA не изменяются и проверяются после теста.

Этот сценарий проверяет установочную транзакцию, ровно один тег, сохранение исходного HTML/JS, личных файлов, повторную установку, 12 прерываний и откат. Он не выдаётся за проверку произвольного настоящего launcher-контракта. Фикстурный manifest и происхождение контракта явно записаны в `INSTALLER_RESULTS.json`.

Реальная установка для текущего d7526… отдельно прошла 21 локальную проверку в `CEF_ADAPTIVE_INSTALL0450.json`; общий статический анализ и настоящий x86 IPC также имеют отдельные доказательства. Ни один production SHA-список ради CI не расширялся. Игровая приёмка и второй компьютер остаются NOT RUN.

Полный Lua-прогон GitHub запускается тем же `tools/run-regression0450.py --jobs 3`, что использовался локально: три независимых процесса, неизменный набор всех 209 групп, проверка отсутствующих/повторённых результатов и хешей исходников. Проверки не сокращаются.
